# ffprobe媒体信息持久化

这是一个 MoviePilot V2 兼容插件。

本插件优先复用“ffprobe命名补充”的内存缓存。缓存命中时立即后台写 JSON；缓存未命中时，最多使用 3 个后台任务进行各 10 秒的 ffprobe 兜底探测。
独立的 MoviePilot V2 兼容插件，用于与 [ffprobe命名补充](https://github.com/DDSRem-Dev/MoviePilot-Plugins/tree/main/plugins.v2/ffprobenamingsupplement) 配合使用。

它优先复用“ffprobe命名补充”在 `TransferRenameBuild` 中缓存的原始 ffprobe JSON。缓存命中时，每个整理文件都会立即启动独立的后台写入，不受并发数量限制，也不阻塞 MP 后续整理、刮削或重命名。若缓存未命中，默认会在 MP 完成该文件的移动、重命名和刮削流程后，以最多 **3** 个后台任务对**最终目标文件**执行一次独立的 `ffprobe` 兜底，超过 **10 秒**即终止并跳过；不会阻塞后续整理任务。关闭“上游缓存缺失时主动提取”后，则始终只复用缓存。

```text
<整理后的媒体文件名>-mediainfo.json
```

JSON 顶层结构兼容 StrmAssistant（神医助手）的 MediaInfo 持久化文件，可避免 Emby 入库后重新探测基础媒体流。

## 必要条件

1. 建议安装并启用 `ffprobe命名补充` 0.2.0 或兼容版本，以便正常流程完全复用它的缓存。
2. 本插件顺序为 51，上游命名插件为 50；二者在同一个 MoviePilot 进程中时才能共享缓存。
3. 如果未安装、未启用上游插件，或上游本次提取失败，本插件可按默认设置自行兜底探测一次（10 秒超时）。

可用“限定整理方式”和“限定整理目标路径”控制范围，每行一个值。筛选条件关系可选：

- `同时匹配`（默认）：每个已填写的条件组都必须命中；另一组留空即视为满足。
- `任一匹配`：只要任意一个已填写的条件组命中即可；留空项不参与判断。

两项都留空时，会处理所有本地媒体文件的整理。

“清理已搬离源文件的同名 MediaInfo JSON”默认开启，且**不受整理方式或目标路径筛选条件限制**。手动从整理历史重新整理、或再次自动整理时，只要 MP 发出该文件的整理完成事件，且源媒体已经不存在、源和新目标路径不同，插件就删除源目录严格同名的 `<旧文件名>-mediainfo.json`。复制、硬链接或源文件仍存在时不会删除，因此不会清理仍在使用的 JSON。

清理发生在 MP 发出 `TransferComplete`（单个文件整理完成）事件时，并放在该条记录的处理逻辑最后执行。它不会等待整批整理任务结束，也没有额外延迟；本条记录的生成、跳过或失败逻辑结束后才做清理检查。

上游命名插件目前只请求流和格式信息、不请求章节；本插件的 JSON 中 `Chapters` 固定为空。
