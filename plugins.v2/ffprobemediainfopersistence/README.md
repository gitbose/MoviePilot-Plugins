# ffprobe媒体信息持久化

独立的 MoviePilot V2 兼容插件，用于与 [ffprobe命名补充](https://github.com/DDSRem-Dev/MoviePilot-Plugins/tree/main/plugins.v2/ffprobenamingsupplement) 配合使用。

它优先复用“ffprobe命名补充”在 `TransferRenameBuild` 中缓存的原始 ffprobe JSON。命中后，本插件立即保存独立的临时副本，再传递到同一条文件的“整理成功”事件；成功事件一到即取出并删除，未完成的异常记录最多保留 12 小时。即使第三方上游缓存后续淘汰，这份副本仍可使用。MP 写入整理历史并给出最终路径后，每个文件都会立即启动独立的后台写入。缓存 JSON 写入不受并发数量限制，也不阻塞 MP 后续整理、刮削或重命名。若本插件暂存和上游缓存均未命中，默认才会在 MP 完成该文件的移动、重命名和刮削流程后，以后台任务对**最终目标文件**执行一次独立的 `ffprobe` 兜底；不会阻塞后续整理任务。兜底任务的并发数可在配置页输入（默认 3，范围 1–10），超时也可单独设置（默认 10 秒、最大 300 秒）。关闭“上游缓存缺失时主动提取”后，则始终只复用缓存。

```text
<整理后的媒体文件名>-mediainfo.json
```

JSON 顶层结构兼容 StrmAssistant（神医助手）的 MediaInfo 持久化文件，可避免 Emby 入库后重新探测基础媒体流。

## 必要条件

1. 建议安装并启用 `ffprobe命名补充` 0.2.0 或兼容版本，以便正常流程完全复用它的缓存。
2. 本插件顺序为 51，上游命名插件为 50；二者在同一个 MoviePilot 进程中时才能共享缓存。
3. 如果未安装、未启用上游插件，或上游本次提取失败，本插件可按默认设置自行兜底探测一次（10 秒超时）。

可用“限定整理方式”和“限定整理目标路径”控制范围，每行一个值。“限定整理方式”可填写：`复制`、`移动`、`硬链接`、`软链接`。筛选条件关系可选：

- `同时匹配`（默认）：每个已填写的条件组都必须命中；另一组留空即视为满足。
- `任一匹配`：只要任意一个已填写的条件组命中即可；留空项不参与判断。

两项都留空时，会处理所有本地媒体文件的整理。

“清理已搬离源文件的同名 MediaInfo JSON”默认开启，且**不受整理方式或目标路径筛选条件限制**。每次整理完成后，插件先等待 10 秒；若媒体文件仍不存在，就删除同目录严格同名的 `<旧文件名>-mediainfo.json`。不关心此次整理使用复制、移动、硬链接还是软链接；媒体文件在 10 秒内恢复或仍存在时不会删除 JSON。

清理任务在 MP 发出 `TransferComplete`（单个文件整理完成）事件的最后提交，随后独立等待 10 秒再检查，不会等待整批任务，也不会阻塞后续整理。

上游命名插件目前只请求流和格式信息、不请求章节；本插件的 JSON 中 `Chapters` 固定为空。
